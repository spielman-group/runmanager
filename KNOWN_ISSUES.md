# Known issues

- `__main__.py`, `RunManager.offer_shot` and `take_default_shot`: a default shot that cannot be made is attempted again on every BLACS request, about once a second while BLACS has no local override shot. A missing default labscript file makes `offer_shot` raise, and the exchange writes a red line each time; a default script that fails to compile is compiled again each time, with its traceback, keeping the compiler busy ahead of Engage's shots. Possible fix, about 49 lines: remember the failure while labscript-utils' `FileWatcher`, hashing, watches the script and the active globals files from the attempt's start. Any event, or a change of policy, script or group activation, releases it, and a generation tag drops a superseded attempt's result. Stop the watcher from another thread, since its callback holds its lock.
- `__main__.py`, `RunManager.on_close_event`: closing while a default shot is being prepared leaves its file in the shot folder, since the preparation hands the shot over after the close has deleted any ready one. Deferred: waiting for it would hold the close on a compile, and deadlock on the preparation's `inmain` read of the active groups.
- `docs/source/conf.py`: `autodoc_mock_imports = ['labscript_utils']` mocks the base class of `RunmanagerClient`, so `runmanager.remote` fails to import in the docs build (`RunmanagerClient.instance()` is missing), and the API reference has no page for the remote client users import.
- `__init__.py`, `find_comments`: offsets after a string spanning lines are too small, so the globals diff and the remote setters' kept comment cut the wrong text (upstream 35ea631).
- `batch_compiler.py`, `BatchProcessor.compile`: `os.chdir` is outside the `try` and `SystemExit` is not caught, so a missing script directory or a script calling `sys.exit` kills the compiler while runmanager waits for its reply (upstream 5bb5e3c).
